## 必须保留的恢复过程

1. 首次运行在原校验下为 5/6，数据目录案例的报告引用过期观察，被程序拒绝且未修改文件。
2. 在该案例原额度内，用一次模型请求从未变的真实观察重建有效报告，再用三次请求完成修复；原校验此时为 6/6，累计 52 次。
3. 人工复核发现拼接补丁根据输入形状改变了显式维度语义。增加同形状输入、显式维度0/2及不兼容输入的反例检查后，实际为 5/6；原弱校验结果保留。
4. 在独立副本中明确接口契约，追加一个最多12次请求的修复任务，实际使用10次，总上限仍为72。该任务重新诊断并移除错误回退，增强校验最终6/6。

因此不能写成“一次全自动修复成功率100%”。拼接修复包含人工反例与契约澄清；验收器增强、报告恢复和全部失败尝试都有独立记录。不同阶段的代码与验收器版本分别留档。
