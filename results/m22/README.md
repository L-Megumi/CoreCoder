# ResearchCoder M22 · JSON Pointer 修复验收

两次真实 DeepSeek Flash 试验均完成修复。检查器从最终候选文件重新导入代码，独立重跑公开复现、故障修复检查和原有行为检查。两份补丁均从同一公开故障版本生成，可分别重放。

| 正常启动 | 从原始缺陷开始，首位 Writer 完成修复 | 1/1 | 4/4 | 7/7 | 13 | 105,822 |

**第二轮的实际改动。** 受控组首轮使用正常工具和 Guard 复现 M19 已归档的错误补丁。第二轮沿用同一 Job 的剩余额度，接收首轮失败的公开检查和与候选摘要绑定的编辑窗口。第二个 Worker 用 4 次真实请求完成 1 次有效编辑，并交付完成报告。本轮前后文件摘要不同，成功的编辑工具事件、进度计数和独立测试结果一致。隐藏检查和参考修复没有进入第二轮指令。两组的首轮条件不同，单例结果应分别解读。

**产品改动。** 可选策略 `edit-window-v1` 仅在真实公开验证失败后的纠错阶段启用。Controller 对授权文件核验原始和当前源码，把实际变动位置附近的连续源码、源码版本和公开失败观察作为数据交接给下一位 Writer。Writer 须重新读取当前文件才能编辑。同一策略修正了回合预留的计数时机，允许倒数第二个已准入回合进行工具操作，最后一次请求留给报告。既有权限、Job 总额度及独立检查保持原口径。

**M21 勘误。** M21 报告写到 JSON Pointer 第二个 Worker 修改了候选文件。复核原始工具回执后确认，当时的 5 次请求对应 4 次读取和 1 次无工具报告。两轮结束时的源码摘要相同，第二轮有效写入为 0。原统计误用了相对初始基线的累计改动。该样本仍为未完成，M21 的历史 E2E 计数没有变化。本次报告同时校验相邻两份 manifest、当前 Attempt 的进度和真实工具回执。

**工程验收。** 最终 Linux 定向测试 60 passed。初次运行留下两个测试夹具失败，原因是脚本专家提供的摘录格式与接收方声明不匹配。按原合同对齐后，全组通过。按约定未进行全量回归。两次真实试验均归档，合计 29 次模型调用，255,655 个实际 Token，Usage unknown 与 pending 均为 0。
