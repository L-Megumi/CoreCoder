# 文件变化与调查快照

本次只完善文件读取和版本一致性，不新增正式测评或模型调用。

## 行为变化

- 每次复用缓存前检查文件签名；跨工具请求的长期读取器还会重新读取有界内容核对哈希，内容未变时复用解析结果。同大小且保留修改时间的改写也不会继续返回旧内容。
- 不再缓存缺失和读取失败，文件创建或恢复后，同一轮调查可再次读取。
- 读取前后核对打开文件和路径的版本，检测到读取过程中变化时返回 `file_changed_during_read`，不提供可能不一致的内容。
- 保留所有旧观察用于追溯。`current_observation_ids` 标明最新已知观察；当前状态和主要源码位置不能引用已被新观察替代的记录。
- 同哈希的分页仍可组合，不同哈希的配置片段不能拼接；新版本只读到尾部时，不借用旧版本的配置头部推断路径。
- 清单、动态工具选择和压缩记忆使用最新已知版本；压缩记忆以 `snapshot_current` 区分旧记录。

可以运行必要的回归测试：

```bash
cd /home/example/ResearchCoder

```

## 边界

“当前”指最新一次工具实际观察到的状态，不表示持续监控磁盘。文件在最后一次观察后仍可能变化。
单次定位调用内部仍可复用同签名快照；跨请求读取器的内容核对会增加有界磁盘读取，不表示减少物理 I/O。
读取前后检查仍依赖文件系统元数据，不是原子文件系统快照，无法保证识别所有并发改写。
验证环境为服务器 Linux。文件哈希只能说明本次读到的内容，不能证明它就是历史报错时的版本。
