### 真实反馈如何进入第二个 Worker

JSON Pointer 第二次试验中，首轮修改通过文件 Guard，但实际公开检查失败。控制器在同一 Job 剩余额度内创建新 Attempt 和独立 Worker，传入与首轮候选版本对应的失败记录。应用层请求归档、API 计量、Artifact 摘要和独立验证共同确认了这次交接。第二个 Writer 实际调用模型 5 次并修改了候选文件。最终补丁把标量判断放在通用序列分支之后，字符串仍先命中序列分支。运行器以 `no_new_evidence` 收尾。这是一次经验证的真实反馈执行，也是一个保留下来的未修复样本。预设的人为触发备选试验没有运行。

### 文件写入拒绝

代码在实际拒绝点生成受控原因，并将同一原因传入 Trace 和 Artifact。可识别当前版本尚未读取、读后发生变化、摘要不可用、文件受保护及路径越界。未分类异常使用通用原因，敏感路径只记录允许的元数据。拒绝的写入仍立即停止。新增 8 个测试，覆盖真实工具调用路径、记录一致性、拒绝伪造分类与敏感信息过滤。历史 M19 SAM 拒绝的具体原因仍未知。

### 验收与计量

- Linux 共 **176 个不同定向测试节点通过**（分批）。首轮有一次测试导入错误，修复导入后，175 个节点通过，1 个测试夹具错误。该夹具原先只检查最后一条消息，未在真实读取回执出现时触发文件变化。修正后新增模块的 8 个节点全部通过。本轮依用户要求未运行全量回归。
- 两个新开发夹具各执行故障版、健康版、取巧补丁三套对照，各有独立公开检查、F2P 与 P2P，共 **18 次检查器调用**。两个取巧补丁均通过公开检查和 F2P，但都因破坏流式行为被 P2P 拦下。它们是新编写的开发案例，单独统计。
- 真实模型为 DeepSeek Flash，非 Thinking。使用相同 Code-first 策略、2,048 输出 Token 和单 Job 22 请求上限，本轮运行的固定源码包含新增的拒绝分类。10 个样本共 **102 次模型请求、116 次工具调用、991,908 个实际 Token**。有 9 个样本实际运行了最终 Oracle，F2P 通过 7/9，P2P 通过 9/9。未评分样本仍保留在 E2E 分母。
- 未知或待结算 API 用量均为 0。按全部输入使用高峰缓存未命中价、输出使用高峰价，费用保守估计为 **US$0.319158**。端到端状态、验证通过、纠错触发、模型用量分别统计。[DeepSeek 价格说明](https://api-docs.deepseek.com/quick_start/pricing/)
- 所有控制器正常结束，无残留受监督 Worker 进程组。私有原始归档包含 Trial、Trace、候选文件、试验快照和摘要；公开投影仅含必要元数据。
