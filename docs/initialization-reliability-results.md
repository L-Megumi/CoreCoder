# 初始化证据与归因可靠性收尾（stage17）

本阶段针对stage16暴露的两个问题：没有读取初始化就猜默认值，以及缺少契约时断言库或调用方无责。通用编程能力和六个诊断工具保留。

## 实现

1. AST为已定位普通实例方法提供本地初始化签名和属性赋值的行号线索；调查清单只接受同路径、同SHA、当前可见片段的实际覆盖，未读就继续读取。范围限于经核对的堆栈方法和已静态解析的方法定义，搜索候选不能触发扩展检查。
2. 初始化源码行进入工具结果、紧凑投影和证据记忆。多行语句、分页、版本变化与超长行均显式处理；继承、动态绑定、缺少唯一本地初始化及分析限额记为未知。
3. 提示要求区分默认值事实、报错机制与责任归属。新增中文词法一致性检查：报告已明确声明无法判断责任时，不允许摘要、当前状态或假设同时无条件排除库缺陷或确定调用方有错。拒绝后复用原有最多一次报告纠正机会，不扩充预算或执行新工具。

## 测试

628项测试全部通过，比stage16新增37项（22项初始化检查、15项报告一致性检查）。修改文件静态检查、全仓严重错误检查和编译检查通过。原有工作流及符号定位完整演示通过；原Agent Loop、模型层、通用上下文与七个编程工具实现保留。

## 明确局限

- 初始化检查只在completion_mode=checklist时强制执行，统一run/chat诊断已启用；独立诊断CLI需显式传入该选项。
- 静态初始化线索不证明运行时绑定、分支执行或接口意图；即使读到默认值，也不能自动确定责任。
- 归因一致性检查只覆盖部分中文显式表述；有漏检可能，不是完整自然语言语义验证器。通过它不意味着根因正确。
- stage16的20%输入Token降幅属于其冻结版本。本轮修复后未重新运行四组消融，因此不宣称当前版本仍有相同降幅。
