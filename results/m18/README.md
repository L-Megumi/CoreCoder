## 实际修正

1. 新增可选择的 streaming-v1 时间分配：专家 45 → 180 秒、writer 90 → 300 秒、Job 180 → 600 秒。旧默认规则和序列化身份保留；未增加角色、调用次数、工具或 Token 权限。
2. 新增 readiness-v3：在专家原有六次请求内，预留报告与一次纠错时隙。保留错误原文和额外调用成本；旧 readiness-v2 的单报告时隙规则仍可复现，严格当前引用校验不变。
3. 新增 focused-repair-v1 写入提示：核查当前目标及少量必要缺口，及时做有依据的最小修改；避免在可编辑阶段反复补查。Prompt SHA 独立记录。
4. 完成 bounded-excerpts-v1 发送/接收合同：按完整引用与来源映射的体积缩短摘录，保留所有原始 ID、生产者、Artifact 和 SHA；接收端按声明的版本与长度核验精确原文前缀。局部视图上限与整体 Token 窗口分开管理，容量错误不再伪装成源码变化。
5. Worker 在模型工厂之前的上下文初始化失败返回明确 input_invalid 与完整零请求计量。旧 R3 缺失响应及其 unknown 责任保留，不回写历史成功。

## 完整试验账本

R1 为四例首轮：2 成功、2 未完成。R2、R3 分别在 Packaging 处停止，SAM 未启动。R4 两例定向复测均成功。累计 **10 个计划样本、8 个已启动并归档样本、2 个未启动样本、4 个成功 Trial，覆盖 4 个成功案例**。全部记录见 trials.json；没有只保留成功样本。

累计 **76 次实际传输请求，851,201 个供应商实际 Token**（输入 832,459，输出 18,742；输入缓存命中 116,480、未命中 715,979）。传输层本轮 unknown/pending 均为 0。原 R3 写入 Worker 的运行账本 unknown 仍独立保留 200,000 Token 责任上限；它不是一个已知的零成本任务成功。M15/M17 的历史 unknown 也未冲抵或删除。

保守准入责任费用为 $0.2722281；按供应商实际缓存用量和已公布非高峰价格后算约 **$0.11899149**，仅为估算，非账单。来源：[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。本轮最多 96 请求、160 万 Token、$1 准入额度；最后两个 Job 各降低到 22 请求。模型通道已关闭，没有待结算传输或残留受监督 Worker。
