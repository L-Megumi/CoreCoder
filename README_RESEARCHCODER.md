# ResearchCoder

面向机器学习研发的 Coding Agent。保留通用代码开发能力，通过日志证据驱动的调查生成诊断报告，再显式交接到代码修改与命令验证。

## 已实现

- **统一工作流入口**：code 保留原有编程工具、会话和交互；diagnose 执行只读调查；repair 核对报告和源码版本后修改代码，依据实际验证命令返回结果。
- **任务路由与会话切换**：run/chat 按用户任务和绑定状态进入编程、诊断、报告解读或显式修复，保留日志/报告关联、切换原因及逐轮记录；支持手动覆盖。
- **执行反馈闭环**：验证失败后保存输出、关联原报告与修改记录，在预算内重新只读诊断；新的明确修复任务使用新报告和当前源码版本。
- **修复证据复用与停止条件**：交接带哈希和行号的源码片段，复用版本一致的重复读取，限制连续调查；修复上下文不额外调用模型，案例预算提前预留。
- **结构化日志证据**：ERROR、WARNING、NaN/Inf、多行 traceback、异常包装因果链，以及稳定证据 ID 与日志行号。
- **源码与配置定位**：按堆栈核对当前代码，支持显式路径迁移、函数范围识别、行号变动和歧义检测；读取配置并记录文件哈希。
- **无堆栈源码调查**：按日志关键词搜索有界 Python 源码，返回带证据 ID、文件哈希、行号和函数范围的候选；读取候选后再诊断，保留未搜索范围与截断原因。
- **函数符号定位与导入关联**：从已读调用追踪项目内函数/类定义，支持常见别名、相对导入和包内重新导出；绑定与定义均保留版本证据，动态情况和歧义明确记录。
- **模型调查闭环**：DeepSeek 根据证据调用六个只读工具，输出历史故障、当前状态、原因假设、验证方法与局限；校验报告结构和引用存在性。
- **Evidence-Guided Tool Selection**：按证据类型与调查进度开放工具，阻止绕过前置步骤的调用，记录每轮选择原因。
- **Evidence-Aware Context Management**：完整证据存储、结构化上下文投影、因果链记忆、完整工具组压缩与显式预算失败。
- **四组对照实验**：baseline、仅工具选择、仅上下文、两项同时开启；分别记录真实提供方用量与离线估计量。
- **调查完成清单**：跟踪未检查证据、源码、历史缺失路径和当前配置路径；在预算内继续过早结束的调查，明确无法确认的项目。
- **受控多类型评测**：7 个说明性故障样例、外部标注隔离、结构化类别/原因/源码行预测与分项评分；失败报告保留在分母中。

## 验收状态

636项工程测试通过；六类真实源码人工注入案例经报告恢复、人工契约澄清和增强校验后最终全部通过，累计62次请求。首次结果及不合格补丁保留，不能作为通用100%修复率或优化收益。详见[分阶段验收记录](docs/project-acceptance-status.md)。

## 四组对照实测（stage16冻结版本）

在六类真实源码注入故障上，每组每例重复两次，共48次只读诊断、183次DeepSeek请求。两项同时开启相对同版基线输入Token由201,141降至160,976（约20.0%）；两组有效报告均12/12，当前故障行有效引用由11/12变为12/12，实际请求数均46次。

仅开启工具选择时故障行引用为10/12，存在覆盖下降。以上为开发案例上的小样本结果，定位引用不等于根因正确；真实运行未触发整组历史淘汰。完整指标、反例和限制见[对照实测结果](docs/controlled-experiment-results.md)。

## 初始化证据与归因可靠性

对已定位实例方法核查构造函数签名与属性赋值，要求同版本实际源码覆盖；继承、动态初始化和截断明确为未知。报告声明责任未知却又排除库缺陷时，新增有限的中文一致性检查并沿用一次报告纠正预算。

本轮10次只读诊断和2次报告纠正共46次请求，全部阶段及不一致报告保留，详见[可靠性验收](docs/initialization-reliability-results.md)。stage16的20%降幅未在新版本重新实测。

## 压缩后真实模型续诊（stage18）
