# 六类真实源码故障的四组对照实验

这是固定功能版本上的诊断消融实验，评估工具选择与证据上下文两项开关。它不比较不同模型，也不比较上游 CoreCoder 和 ResearchCoder 的总体能力。基线同样拥有六个诊断工具、静态符号定位、调查清单及引用校验，仅关闭这两项优化。

## 预先固定的设计

| 组 | tool_selection | context_mode |
| --- | --- | --- |
| baseline | all | baseline |
| tools | guided | baseline |
| context | all | evidence |
| both | guided | evidence |

六种故障是验证集路径、类别数、卷积输入通道、默认拼接维度、IoU 稳定项和导入名称。控制器在 M2D-LIF 新副本中执行健康检查，注入故障，再执行失败检查并生成真实日志。原始项目、数据集和权重不参与修改。

每个案例、每组重复两次，共48次独立诊断会话。同一个案例的四组读取相同的只读源码和日志，运行后检查哈希。随机种子42只控制案例与组的执行顺序；不控制模型生成或提供方缓存。请求温度统一为0，仍不保证输出确定。

四组共用8轮调查、16次工具请求、1次报告纠正机会、128000估计上下文Token预算及调查清单。没有源码入口提示、人工契约提示、跨会话记忆或失败后恢复。报告未通过校验也计入总体。每个会话最多10次底层API请求，总上限480次；未使用的额度不会增加另一会话的额度。SDK及模型包装层均关闭自动重试；不支持stream_options导致的兼容性重发也作为新请求计数。

控制器先落盘manifest，再接触模型。manifest包含顺序、开关、固定预算、源码及日志哈希。每次底层请求先落盘账本，再发送。账本包含实际模型标识、Token、缓存用量（接口返回时）、流状态和耗时，不保存密钥及提供方错误正文。目标输出目录和账本不能覆盖；本入口不提供自动续跑，异常中止时保留已完成记录。

## 指标定义

1. **报告有效率**：最终JSON通过现有结构、引用、当前观察版本等校验。它不代表结论语义正确。
2. **故障行观察覆盖率**：实际返回的源码/配置片段具有被注入文件的SHA，实际可见行覆盖至少一个标注故障行。行号上限不以被截断前的end_line计算。
3. **有效报告故障行引用率**：报告有效，且至少一个假设引用了当前版本、覆盖故障行的观察。这是定位与证据连接指标，不是根因准确率。
4. **开销**：实际底层请求次数、输入/输出Token、工具请求数、工具错误数、工具schema字符量及耗时。所有失败会话一并计算。实际用量缺失时明确标记，不用估计值补成计费Token。
5. **配对差异**：按同一案例和重复编号配对，比较三个优化组与baseline的Token和调用量。表中百分比基于包含失败在内的总量；同时报告有效率，避免将提前失败误认为效率提升。

人工根因复核如另行提供，会明确标注评审者、预定判据、报告有效性和是否引用故障行；不把该复核写成独立盲测。没有自然故障留出集或多名评审，因此不报告通用根因准确率。

## 长上下文机制检查

同时运行既有离线检查：异常因果链、无堆栈数值异常、长异常消息三种人工转录，加入无关工具输出触发压缩。比较压缩后可直接从JSON读取的固定事实，包括证据ID、因果边或NaN/Inf、路径存在/缺失状态。

该检查没有API调用，baseline使用无模型摘要的回退路径；结果只证明结构化事实保留机制，不能证明真实模型摘要质量、语义记忆或真实长任务成功率。真实四组实验若没有触发整组历史淘汰，必须说明其上下文收益主要来自工具结果投影，不能宣称验证了长期记忆效果。

## 复现

```bash
cd /home/example/ResearchCoder
PYTHONPATH=. /home/example/miniforge3/envs/researchcoder/bin/python examples/m2d_ablation.py \
  --source /home/example/M2D-LIF \
  --experiment-python /home/example/miniforge3/envs/M2D/bin/python \
  --output-dir /home/example/ResearchCoder/.tmp/ablation-new \
  --env-file /home/example/ResearchCoder/.env --direct --repeats 2 --seed 42 --live
```

省略`--live`会构造并验证案例、运行离线机制检查、保存计划，不调用API。输出目录必须尚不存在；新增目录另行运行将产生一轮新的实验及相应API用量。

## 解释范围

案例来自已用于开发和验收的六类故障，不能称为独立测试集、公开基准或全面深度学习诊断覆盖。两次重复只提供小样本描述；同一案例的重复不视为两个独立故障。耗时包含网络、模型生成和工具运行，提供方缓存及服务负载不受控，不据此承诺速度或费用降幅。

本轮只比较只读诊断。自动修复能力由另外的独立验证器验收记录支持；不能将此前包含报告恢复和人工契约澄清的6/6最终结果并入本轮对照成功率。
